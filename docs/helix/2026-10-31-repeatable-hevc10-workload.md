# Repeatable real HEVC10 workload — implementation checkpoint

This successor preserves `392bb662ed20c6866af0942d219359518a885193` and its frozen runtime artifacts. It advances decoder reliability and repeatable packet-recovery characterization. It does not promote or alter the old encoded-loss stability verdict.

## Contract

The workload is generated once with seed 20261031, torture profile and 300-second duration from the existing VRChat model and a retained measured pacing log. The selected calibration capture is `/home/chineko/helix-blackout-20261029-191648-reduced/server-log.txt`; it is copied and hashed into the bundle. Existing model priors retain their measured/assumed labels. The first 15 seconds are reserved for the existing canaries at encoded ordinals 600 and 900. The generated scenario has 26,933 stereo production entries, six producer-stall intervals and eight shared path events.

The old model parser only recalibrates some fields and leaves `shards_mean=21` from a different capture. Initial preparation correctly failed its unchanged shard-count tolerance. This successor computes measured mean shard count from actual shard/frame totals for the two eye summaries; it does not loosen any calibration tolerance or adjust the seed after a device result. The previous frozen trace remains unchanged.

The new Vulkan/OpenXR app reuses the local graphics-bound stimulus's ownership/session/render path. It submits the generated absolute production schedule, selecting one of 32 deterministic entropy levels independently per eye from the generated byte targets. Encoded bytes are never padded or truncated to manufacture agreement. The byte targets are a complexity surrogate, not a guarantee of NVENC size. Actual frame size/cadence summaries have a separate calibration verdict. Producer gaps must be measured; an application stall may not map exactly to a compositor/encoder stall. This is not a simulation of VRChat avatar rendering, CPU load, or shader cost.

Real NVENC H.265 Main10 packets, including RTX, pass through a session-owned shared FIFO path scheduler after encoding and before UDP serialization. Loss/hold/drain events apply to both eyes on one monotonic origin. The scheduler is opt-in through an explicit plan; ordinary runs retain their existing send path. It starts lazily after the server fork, copies payload ownership, bounds queued packets to 4096 and payload bytes to 8 MiB, and fails rather than silently dropping on capacity exhaustion. Every injected path drop records exact stream/frame/packet sequence. Actual RTX send completion has an additional event. Teardown reports failures, cancellations, peaks and scheduling lateness. The declared timing-integrity limit is 3 ms maximum worker lateness; violation is nondiagnostic for the representative timing question and fails the runtime gate.

The small heap and scheduling overhead of this queue is an observer/intervention effect. The 32-image stereo host-visible staging bank can consume roughly a gigabyte at common headset resolutions; it is allocated once, not per frame. This lane characterizes traffic and decoding, not equivalent rendering resource pressure.

## Observer fixes and oracle

Assembly probes are now inserted before `push_data()` can queue a complete MediaCodec input. Accepted retransmitted shard-0 packets emit exact received packet sequences. A new decoder epoch clears old process-static probe slots and logs its epoch. The experiment permits one decoder epoch per eye and rejects any flush/recreation; it does not pretend that clearing counters is verified recovery across generations.

For EACH eye, require exactly one frozen canary drop; matching server frame/sequence, queued RTX and actual RTX delivery; matching accepted shard-0 frame/sequence at the receiver; complete assembly; exact MediaCodec output; and AImage at/after the same recovered frame. Require per-process causal event order, both resolved Main10 gates, one decoder epoch, final fault/probe summaries, overflow=0 and no path failure/cancellation. No host/headset timestamp subtraction is used. `sent_to_decoder` and aggregate recoveries cannot replace any link. Pixel cleanliness remains NOT_ESTABLISHED.

Because the representative impairment can discard many frames, not every damaged frame is required to recover. Canary evidence is the functional decoder gate. Representative traffic fidelity is assessed separately against the measured mean, peak and cadence. Failure to match cannot become a VRChat-like PASS merely because the canaries decode. The image event establishes AImage availability, not clean pixel contents or successful final compositor presentation.

No dashboard or prefix script participates. Existing trust is reused; missing pairing is a bounded failure, not an authentication bypass. Logs, identity records, failure results and evidence hashes are retained. Any failure removes the active audit gate and requires complete re-audits before another device attempt. There are no automatic repeated device retries.
